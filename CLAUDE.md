# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

A **static HTML/CSS/JS prototype of the DIGITECHKH POS**, in Khmer, with two roles: **cashier** (built) and
**manager / supervisor** (planned — see `src/manager/README.md`). It was split out of the eBMS repo (`ebms_digitechkh`,
role 05) and covers only the POS. There is no build system, no tests and no backend.

```bash
python3 -m http.server 8000 --directory src   # then open localhost:8000
```

Verification is visual: open the page in a browser, or screenshot it with headless Chrome. Serve over HTTP; `file://`
storage is unreliable.

## Layout

```
src/
├── index.html                    redirect to cashier/terminal/pos-terminal.html
├── cashier/<feature>/<page>.html terminal/{pos-terminal,khqr-payment}, receipts/receipts, shift/close-shift
├── manager/<feature>/<page>.html (planned)
└── shared/{scripts,styles,assets}
```

- **Every page is exactly two levels below `src/`** and carries `data-role-root="../.."`. That attribute is the path to
  `src/` (the name is inherited from eBMS). `portal.js` builds nav links, logo and avatar paths from it, and `data.js`
  builds product image paths from it. A page at another depth breaks those links.
- Nav hrefs in `PORTAL_CONFIGS` (`portal.js`) are relative to `src/`, e.g. `cashier/receipts/receipts.html`.
- Links written in a page's own markup are relative to that page (`../receipts/receipts.html`). `data-back` too.
- Logout goes to `index.html`, since there is no login page yet.

## How a page is assembled

- `<body id="posPortal" data-role-root="../.." data-active="pos">`. `id` selects the `PORTAL_CONFIGS` entry and scopes
  `portal.css`; `data-active` picks the highlighted nav item.
- The sidebar is generated by `renderPortalSidebar()` into `<div id="sidebarHost"></div>`. Change nav in `portal.js`,
  never in the pages.
- Script order: `shared/scripts/ui-components.js` → `shared/scripts/data.js` → `shared/scripts/portal.js` → the page's inline `<script>`.
- Adding the manager role: create `src/manager/<feature>/<page>.html`, add a `managerPortal` entry to `PORTAL_CONFIGS`,
  and use `<body id="managerPortal" ...>`. Manager pages read the same `data.js`.

## Data (`shared/scripts/data.js`)

All data is fake and generated relative to today. Nothing numeric is hard-coded in markup.

- Constants: `FX_RATE` (4100 KHR/USD), `SHIFT`, `VARIANCE_TOLERANCE`, `CATEGORIES`, `PRODUCTS`, `CREDIT_CUSTOMERS`, `USD_NOTES` / `KHR_NOTES`.
- Helpers: `fmtUSD`, `fmtKHR`, `toKHR`, `toUSD`, `saleTotals`, `findByBarcode`, `productImgHtml` …
- Storage: `pos_shift_sales`, `pos_cart` and the pending payment are in `sessionStorage`; the shift state is in `localStorage`.
- Product images are `shared/assets/products/<sku>.png`; a missing image falls back to an icon automatically.

## Inherited from eBMS

`portal.js`, `ui-components.js`, `custom.css` and `portal.css` came from the eBMS repo's `frontend/shared/`.
`PORTAL_CONFIGS` was cut down to `posPortal`, but the code still has branches for other portals (e.g.
`PORTAL_USES_STORE`, the non-V2 sidebar renderer). They are inactive here; remove them only when touching that code.
`shared/assets/avatars/` has no image, so the avatar shows initials.

## Mandatory standards

Read [GEMINI.md](GEMINI.md) and [.ai/ui-rules.md](.ai/ui-rules.md) before changing a page. Their file paths refer to the
old eBMS layout; the rules apply as-is. Condensed:

| Rule | Requirement |
|---|---|
| Language | 100% Khmer UI text. No English words, none in parentheses. Brand names (`KHQR`, `Bakong`) are fine. |
| Numerals | Arabic numerals (`0-9`) everywhere, never Khmer numerals. |
| No native UI | No `<select>`, `alert()`, `confirm()` or native tooltips. Use `showToast()`, `showCustomConfirm()`, the custom dropdown. |
| Reasons | Voiding or rejecting needs a reason: `showReasonPrompt()` in `ui-components.js`. |
| Header | Sidebar brand block and `<header>` are both `h-[72px] px-6 flex-shrink-0`. |
| Back button | Icon-only, byte-identical on every sub-page (GEMINI.md §5). |
| Full width | `<main>` uses `w-full`, never `max-w-* mx-auto`. |
| Table actions | One `⋮` button opening a floating menu. |
| Typography | `Kantumruy Pro`; headings `font-semibold`, rows `font-medium`; prefer `text-slate-700/600` in tables. |
| Money summary | subtotal → down payment → special discount → VAT 10% → grand total. Dual currency USD/KHR. |
| Printing | Receipts print to 80mm thermal, the Z-report to A4, via `@media print`. |
| Em dash | Don't put «—» between Khmer phrases; a lone «—» as an empty-value marker is fine. |

## `custom.css` traps

- It overrides Tailwind's type scale with `!important` (`.text-xs` = 14.5px, `.text-sm` = 15.5px, `.text-base` = 16.5px).
  Check it before debugging any font size. Restore hierarchy with ID-scoped rules (`#posPortal ...`).
- `hidden sm:inline` never shows; round elements are forced to 13.5px.
- It hides scrollbars globally and holds the `< 1024px` off-canvas drawer rules.
