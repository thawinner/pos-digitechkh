# គោលការណ៍រចនាប្រព័ន្ធ UI នៃគម្រោង BMS DigiTech

ឯកសារនេះកត់ត្រាចំណង់ចំណូលចិត្ត និងស្តង់ដារ UI/UX ដែលបានកំណត់ដោយអ្នកប្រើប្រាស់សម្រាប់គម្រោងនេះ៖

---

## ១. ហាមដាច់ខាតការប្រើប្រាស់ Browser Native UI (Default Elements)

| ធាតុ Native ដើម | បញ្ហា | ដំណោះស្រាយជំនួស (Custom Components) |
|---|---|---|
| **Native `<select>`** | Menu ធ្លាក់ចុះជាទម្រង់ OS Classic (ពណ៌ខៀវរឹង, មិនអាច Style បាន) | បង្កើត **Custom Dropdown Component** (ប៊ូតុងចុចបើក Menu `div` មានរូប Icon, Avatar, Shadow ទន់ភ្លន់, Hover ស្អាត) |
| **`window.alert()`** | ផ្ទាំង Pop-up ដើមរបស់ Browser គ្មានសោភ័ណភាព | បង្កើត **Custom Toast Notification** (អណ្តែតនៅជ្រុងខាងស្តាំក្រោម/លើ មានចលនា Slide-in និងបិទស្វ័យប្រវត្ត) |
| **`window.confirm()`** | ប្រអប់ Confirm ដើមរបស់ Browser មើលទៅដូចប្រព័ន្ធចាស់ | បង្កើត **Custom Confirm Modal** (ប្រអប់សួរបញ្ជាក់មាន Icon ព្រមាន, ប៊ូតុង បោះបង់ និង យល់ព្រម ស្អាតតាមប្រព័ន្ធ) |
| **Native Tooltip** | អក្សរខ្មៅតូចដើម | ប្រើ Styled Tailwind Tooltips ឬ Popover |

## ២. គោលការណ៍ទម្រង់បង្កើត និងកែប្រែ (Dedicated Pages & Unified Back Button Standard)
- **ហាមដាច់ខាតការប្រើប្រាស់ Modal Dialog Pop-up** សម្រាប់ទម្រង់បង្កើតថ្មី (Add/Create) ឬទម្រង់កែប្រែ (Edit)។
- រាល់មុខងារបង្កើតថ្មី និងកែប្រែទាំងអស់ (ដូចជា បង្កើតសម្រង់តម្លៃ, បង្កើតវិក្កយបត្រ, បង្កើតអតិថិជន) ត្រូវតែរៀបចំជា**ទំព័រពេញលេញដាច់ដោយឡែក (Dedicated Full Page)** ដែលមានប៊ូតុងត្រឡប់ក្រោយស្តង់ដាររួម និងប្លង់ទម្រង់ទូលាយកម្រិតសហគ្រាស (Enterprise Layout)។
- **ស្តង់ដារប៊ូតុងត្រឡប់ក្រោយ (Unified Back Button Standard)**៖
  គ្រប់ទំព័ររង (ដូចជា `create-[feature].html`, `edit-[feature].html`) ត្រូវតែប្រើប្រាស់ប៊ូតុងត្រឡប់ក្រោយជាប្រអប់មូលកោងមានរូបសញ្ញាព្រួញតែមួយគត់ (Icon-only rounded-square button) ដូចគ្នាបេះបិទ ១០០%៖
  ```html
  <a href="[feature].html" 
     class="w-10 h-10 rounded-xl bg-slate-50 hover:bg-slate-100 text-slate-600 flex items-center justify-center transition border border-slate-200/70" 
     title="ត្រឡប់ទៅ...">
      <i class="fas fa-arrow-left text-sm"></i>
  </a>
  ```
  ហាមដាច់ខាតការសរសេរអក្សរវែងក្នុងប៊ូតុង ឬការប្រើប្រាស់របារខណ្ឌ (`divider`) ដើម្បីធានាបាននូវភាពស្អាតស្អំ ស្រាលភ្នែក និងស៊ីសង្វាក់គ្នាជាសកល។


---

## ៣. គោលការណ៍ភាសាខ្មែរ (Strict Khmer Language Rule)
- អត្ថបទទាំងអស់លើ UI ទាំងមូល និងរាល់ការពន្យល់ឆ្លើយតប ត្រូវតែជា**ភាសាខ្មែរសុទ្ធសាធ ១០០%**
- គ្មានការសរសេរពាក្យអង់គ្លេសលាយឡំ ឬពាក្យក្នុងរង្វង់ក្រចកជាភាសាអង់គ្លេសឡើយ។

---

## ៤. គោលការណ៍រចនាកាត និងប្លង់ទំព័រ (Clean Minimalist Design & Full Width)
- **ប្លង់ទំព័រពេញទទឹងអេក្រង់ (Full Width Layout)**៖ គ្រប់ទំព័រទាំងអស់ រាល់មាតិកាក្នុង `<main>` ត្រូវតែប្រើប្រាស់ `w-full` ដើម្បីលាតសន្ធឹងពេញផ្ទៃអេក្រង់ ១០០% ហាមដាច់ខាតការប្រើប្រាស់ `max-w-* mx-auto` (ដូចជា `max-w-5xl` ឬ `max-w-7xl`)។
- **គ្មានរូបតំណាង Watermark ធំៗ** នៅជ្រុងកាតស្ថិតិឡើយ (រក្សាភាព Clean & Data-focused)
- ជួរឈរសកម្មភាពក្នុងតារាងត្រូវប្រើប៊ូតុង **`⋮`** តែមួយជាមួយ Floating Action Menu
- **កម្ពស់ក្បាល Sidebar និង Content Header ស្មើគ្នាពិតប្រាកដ**៖ ទាំងក្បាល Sidebar ម៉ាកយីហោ (`div.h-[72px]`) និង Content Header (`header.h-[72px]`) ត្រូវកំណត់កម្ពស់ថេរ `h-[72px] px-6 flex-shrink-0` ដូចគ្នា ១០០% ដើម្បីឱ្យបន្ទាត់បាត (Divider line) ផ្គុំគ្នារត់ត្រង់ជួរផ្ដេកតែមួយឥតខ្ចោះ។
- **លាក់របាររំកិលទាំងអស់ជាសកល (Globally Hidden Scrollbars)**៖ រាល់ទំព័រត្រូវលាក់ Scrollbar ទាំងផ្តេក និងបញ្ឈរ ដោយរក្សាដំណើរការរំកិលបានរលូនធម្មតា។
- ប្លង់មាតិកាសំខាន់ (Main Container) ត្រូវមានគម្លាតស្មើគ្នា `px-4 md:px-6 py-4`

---

## ៥. រចនាសម្ព័ន្ធថត និងទំព័រមុខងារនីមួយៗ (Modular Feature Subfolder Standard)
- មុខងារកូននីមួយៗក្នុងម៉ូឌុល (ដូចជា ការលក់ `sales/`, ការទិញ `buy/`, ស្តុក `stock/`) ត្រូវមានថតរងដាច់ដោយឡែក (Subfolder per child feature)
- រាល់ថតរងនីមួយៗត្រូវរៀបចំឯកសារជា ៣ ទំព័រគោល៖
  1. `[feature].html` (ឧ. `invoice.html`, `quote.html`)៖ ទំព័រតារាងបញ្ជីទិន្នន័យមេ (List View)
  2. `create-[feature].html` (ឧ. `create-invoice.html`, `create-quote.html`)៖ ទំព័រទម្រង់បង្កើតទិន្នន័យថ្មី (Create Form Page)
  3. `edit-[feature].html` (ឧ. `edit-invoice.html`, `edit-quote.html`)៖ ទំព័រទម្រង់កែប្រែទិន្នន័យ (Edit Form Page)
- ហាមដាច់ខាតការដាក់ឯកសារលាយឡំគ្នាក្នុង Root Folder ដោយគ្មានការបែងចែកថតរង ដើម្បីភាពស្អាត និងងាយស្រួលគ្រប់គ្រង (Clean & Modular Architecture)។

---

## ៦. ស្តង់ដារតម្រងកាលបរិច្ឆេទរួម (Unified Date Range Picker Standard)
- គ្រប់ទំព័រដែលមានតម្រងកាលបរិច្ឆេទ (ដូចជា វិក្កយបត្រ, សម្រង់តម្លៃ, ផ្ទាំងគ្រប់គ្រង Dashboard) ត្រូវតែប្រើប្រាស់ Component ដូចគ្នាបេះបិទ ១០០% តាមគំរូទំព័រវិក្កយបត្រ (`invoice.html`)៖
  1. **ប៊ូតុងចុចបើក (Trigger Button)**៖ មានផ្លាក «កាលបរិច្ឆេទ:», រូបតំណាងប្រតិទិន `fa-calendar-days text-primary`, អត្ថបទចន្លោះកាលបរិច្ឆេទ (ឧ. «1 កញ្ញា - 30 កញ្ញា»), និងសញ្ញាព្រួញ `fa-chevron-down`។
  2. **ផ្ទាំងទម្លាក់ចុះ (Popover `w-[480px]`)**៖
     - **ជួរឈរខាងឆ្វេង (Presets ១០ ជម្រើស)**៖ ថ្ងៃនេះ, ម្សិលមិញ, សប្តាហ៍នេះ, សប្តាហ៍មុន, ខែនេះ (Default Active `bg-[#0f2b5c]`), ខែមុន, ឆ្នាំនេះ, ៧ ថ្ងៃចុងក្រោយ, ១៤ ថ្ងៃចុងក្រោយ, ៣០ ថ្ងៃចុងក្រោយ។
     - **ជួរឈរខាងស្តាំ (Calendar Grid)**៖ ក្បាលខែឆ្នាំ មានប៊ូតុងរំកិលខែ `< >`, ឈ្មោះថ្ងៃជាភាសាខ្មែរ (ច, អ, ព, ព្រ, សុ, ស, អា ចាប់ផ្តើមពីថ្ងៃចន្ទ), និងក្រឡាថ្ងៃជ្រើសរើសចន្លោះ (Range Selection) មានគែមមូល និងពណ៌ navy `#0f2b5c`។
     - **ផ្នែកខាងក្រោម (Footer)**៖ មាន Capsule Tag បង្ហាញកាលបរិច្ឆេទដែលបានរើសជាមួយប៊ូតុង `x` សម្អាត, ប៊ូតុង «បោះបង់», និងប៊ូតុង «ជ្រើសរើស» (`bg-[#0f2b5c]`)។

## ៧. គោលការណ៍ UX/UI សម្រាប់អ្នកប្រើពិត (Customer-facing UX)
ប្រព័ន្ធនេះសម្រាប់បុគ្គលិកហាង (អ្នកគិតលុយ អ្នកគ្រប់គ្រង ម្ចាស់ហាង) មិនមែនសម្រាប់អ្នកសរសេរកម្មវិធីទេ។ រាល់ការកែប្រែត្រូវធ្វើឱ្យការងាររបស់ពួកគេលឿនជាងមុន ច្បាស់ជាងមុន ឬមានសុវត្ថិភាពជាងមុន។

**រូបរាង៖ សាមញ្ញ ស្ងប់ និងមានវិជ្ជាជីវៈ**
- ផ្ទាំងពណ៌ស បន្ទាត់ព្រំដែនពណ៌ប្រផេះស្តើង អក្សរពណ៌ប្រផេះ (slate)។ ពណ៌ចម្បងតែមួយគត់គឺ **ខៀវ** (`#2563EB`) សម្រាប់ប៊ូតុងចម្បង ផ្ទាំងសកម្ម និងតំណ។ ហាមប្រើ indigo, cyan, sky, teal, purple។
- ហាមការតុបតែង៖ គ្មាន gradient, ស្រមោលពណ៌, កាតពណ៌ស្រាល, ប្រអប់រូបតំណាងពណ៌ ឬបន្ទាត់ពណ៌ខាងឆ្វេង។
- ពណ៌មានន័យតែប៉ុណ្ណោះ៖ ក្រហម = កំហុស ឬការខាតបង់ ឬសកម្មភាពលុប · លឿង = ត្រូវយកចិត្តទុកដាក់ ឬកំពុងរង់ចាំ · បៃតង = កំពុងដំណើរការ ឬការកើនឡើង។ បន្លិចតែករណីខុសប្រក្រតី ជួរធម្មតា (ស្តុកគ្រប់គ្រាន់ បានអនុម័ត បានបញ្ជាក់) ប្រើពណ៌ប្រផេះ។
- តួលេខប្រើពណ៌ប្រផេះងងឹត ដាក់ពណ៌តែពេលត្រូវការការយកចិត្តទុកដាក់។ ប្រភេទ (វិធីទូទាត់ តួនាទី ប្រភេទចលនា) ជាអត្ថបទធម្មតា មិនដាក់ពណ៌ទេ។
- ប្លង់តឹង៖ ជួរតារាងប្រហែល 52px មិនសរសេរពន្យល់ស្ទួនពីក្រោមចំណងជើង ប៊ូតុង `⋮` គ្មានស៊ុម។

**ឥរិយាបថ៖ រចនាសម្រាប់បុគ្គលិក មិនមែនអ្នកអភិវឌ្ឍន៍**
